Fund Exposure Model Manual

Returns-based attribution of hedge fund drivers from monthly fund returns (about 60 months each) and Bloomberg index data. The model runs two levels: five asset-class buckets first, then regional and style drill-downs. Follow the stages in order. Every stage ends with a gate that must pass before the next stage starts.

00Scope and principles

Question answered: which market factors explain each fund's monthly returns, how much of its variance each explains, and whether each exposure is statistically and economically real.

What this is not: a causal model or a return forecast. A "driver" here means a persistent, explainable co-movement with a tradable factor.

Design principles
  • Estimation risk is the binding constraint. With about 60 observations, keep 5 to 8 parameters per fund at most.
  • Use long index history, short fund history. Indices have 10 to 20+ years of data. Build and orthogonalize factors on that long window, and use the fund's 60 months only to estimate its betas.
  • Fixed core, selected extras. The five bucket factors enter every fund regression, which makes funds comparable. Only drill-down factors are selected.
  • Selection happens inside validation. Any factor selection is re-run within each walk-forward step. Otherwise out-of-sample statistics are biased upward.
  • Everything is additive. Level 2 contributions sum exactly into their Level 1 bucket.

01Data preparation

Purpose

Produce one clean monthly panel of fund excess returns and one of index returns, aligned on month-end dates.

Procedure: fund returns
  1. Store returns as decimals (0.012, not 1.2%), net of fees, one row per fund-month, dated at calendar month-end.
  2. Record for each fund: base currency, strategy bucket (e.g. Equity L/S, Credit, Macro, CTA, Relative Value, Multi-Strategy), region focus, inception date, and data source.
  3. Convert non-base-currency share classes to one reporting currency (USD, or the class the portfolio actually holds). Hedged classes: use hedged returns and treat FX exposure as near zero by construction.
  4. Backfill bias: if the database reports an addition date, drop the months before it, or flag them.
  5. Gaps: do not interpolate. A fund with a missing month is estimated on available months only. Funds with fewer than 48 valid months are reported but marked low confidence.
  6. Outliers: flag any month with |z| > 4 versus the fund's own history and verify it against the source. Do not winsorize fund returns; the extreme months often carry the exposure information.
  7. Compute excess return: r_fund − r_f, where r_f is the 1-month T-bill return (or the local cash rate for non-USD funds).
Procedure: index returns
  1. Pull month-end levels of total return indices. Use price-return indices only when no total return version exists, and log the exception.
  2. Compute simple returns: R_t = P_t / P_(t−1) − 1.
  3. Level series (VIX, yields, spreads) are not returns. Convert them to first differences (ΔVIX, Δyield) and tag them as type = level_change.
  4. Pull the longest history available, at least 120 months, and ideally from 2005 so that 2008 is included.
Outputfund_panel.parquet, index_panel.parquet, fund_meta.csv, and a data-quality log.
GateEvery fund has a strategy bucket and currency. Every outlier has been verified. Dates align on month-end.

03Factor selection funnel

Purpose

Reduce hundreds of indices to a small, non-redundant factor library, without looking at fund returns. This stage uses index data only, so it cannot overfit to the funds.

Filter A: Eligibility

  • History covers the full fund window plus 24 months.
  • Total return or excess return type preferred (price-return only as a documented exception).
  • Investable = Y preferred. Non-investable indices are allowed only if no investable substitute exists.
  • Currency consistent with the reporting currency, or convertible.

Filter B: Redundancy clustering (within each bucket)

  1. Compute the correlation matrix of monthly returns over the long window (at least 120 months).
  2. Run hierarchical clustering (average linkage) with distance d = 1 − |ρ|.
  3. Cut the tree at d = 0.10, so indices correlated above 0.90 fall in the same cluster.
  4. Keep one representative per cluster, in this priority order: broadest coverage, then investable, then longest history, then most commonly used by the desk.

Example: S&P 500, Russell 1000, MSCI USA and Nasdaq-100 usually collapse into one US equity representative. Keep Nasdaq separately only if a growth or tech factor is part of the plan, and then as a spread (see Stage 04).

Filter C: Level 1 assignment

BucketLevel 1 factor definitionNotes
EquityGlobal equity TR (e.g. MSCI ACWI) minus rfLocal or USD, consistent with funds
RatesGlobal Treasury TR, hedged to USD, minus rfPure duration
CreditGlobal corporate excess return over duration-matched TreasuriesAlready net of rates; do not subtract rf
CommodityBroad commodity TR (e.g. BCOM TR) minus rfTR includes collateral yield
FXUSD basket return (e.g. DXY or trade-weighted USD)Sign: positive = USD appreciates

Filter D: Candidate budget

  • Level 2: at most 4 to 5 candidates per bucket (for equity: US base, Europe, Japan, EM, and optionally China or Asia).
  • Level 3: at most 6 to 8 total (for example size, value, momentum, quality, ΔVIX, trend-following).
  • Total candidate pool: 25 or fewer. More candidates means more false selections, whatever method you use.
Outputfactor_spec.yaml: the list of Level 1, Level 2 and Level 3 factors with construction rules.
GateWithin-bucket correlation of retained candidates is ≤ 0.90. Pool size is ≤ 25. The spec is signed off and frozen for the quarter.

04Factor library build

Purpose

Turn the selected indices into clean, interpretable, low-collinearity factor return series.

  1. Level 1: compute excess returns as defined in Stage 03. Check the 5×5 correlation matrix. Equity and Credit are typically 0.6 to 0.7 correlated. This is acceptable because credit is measured as an excess return, but always report VIF in Stage 06.
  2. Level 2 spreads: for each regional index j in bucket k, compute
    S_j = R_j − R_global,k
    Drop one region per bucket as the base (usually the largest weight, e.g. US in equity), because the regional spreads are nearly linearly dependent on the global index.
  3. Orthogonalize each spread (and each Level 3 factor) against all five Level 1 factors, over the long window:
    S_j,t = a + Σ_k b_k · F_k,t + u_t → S̃_j,t = u_t
    Store the coefficients (a, b). In walk-forward testing, re-estimate them using only data up to the test date.
  4. Level 3 style factors: construct as long-short spreads (small minus large, value minus growth, momentum minus market) and orthogonalize the same way. ΔVIX enters as a monthly change, orthogonalized.
  5. Trend-following: use a published CTA or trend index return as the factor, orthogonalized. Use the Fung–Hsieh lookback straddle factors if you have them.
Why orthogonalize: Level 1 betas stay the same whether or not Level 2 factors are added, so the attribution is additive and reconciles across levels. Each Level 2 beta measures a tilt relative to the global exposure.
Outputfactors_L1.parquet, factors_L23.parquet, ortho_coefs.parquet.
GateCorrelation of each S̃ with every Level 1 factor is ≈ 0 (< 0.05) over the long window. All VIFs are < 5.

05Fund diagnostics

Purpose

Check each fund's return series before modelling, and correct for return smoothing.

  1. Compute n, annualized mean and volatility, skew, kurtosis, maximum drawdown, the first-order autocorrelation ρ1, and the Ljung–Box p-value at 3 lags.
  2. Smoothing test: if ρ1 > 0.20 and the Ljung–Box p < 0.05, the fund is smoothed. This is common in credit, distressed and private-asset-heavy funds.
  3. Unsmoothing (default: Geltner):
    r*_t = (r_t − ρ₁ · r_(t−1)) / (1 − ρ₁)
    Run the model on both raw and unsmoothed returns. The unsmoothed run is primary. Report both.
  4. Alternatively, fit Getmansky–Lo–Makarov MA(2) weights by MLE when the lag structure extends beyond one month.
Outputfund_diag.csv with a smoothing flag and the series to use.
GateEvery fund has a decision: raw or unsmoothed.

06Level 1: bucket model

Purpose

Estimate each fund's exposure to the five asset-class buckets and the share of its risk each explains.

6.1 Regression (fixed specification, all funds)

r_t = α + β_EQ·EQ_t + β_RT·RT_t + β_CR·CR_t + β_CM·CM_t + β_FX·FX_t + ε_t
  • OLS with Newey–West (HAC) standard errors, 3 lags.
  • Keep all five factors even if insignificant. This fixed specification keeps funds comparable. Report insignificant betas as "no material exposure."
  • Report R², adjusted R², α (annualized) with its t-stat, residual volatility, VIF for each factor, and the Durbin–Watson statistic.

6.2 Peer shrinkage (empirical Bayes)

Apply when a strategy bucket has at least 8 funds. For each factor k within the peer group:

τ²_k = max( Var_cross(β̂_k) − mean(se²_k), 0 )
w_i,k = τ²_k / (τ²_k + se²_i,k) β^shrunk_i,k = w·β̂_i,k + (1 − w)·mean_peer(β̂_k)

Noisy funds move toward the peer mean. Precisely estimated funds keep their own beta. Report shrunk betas as primary, and keep the raw OLS betas alongside.

6.3 Risk shares

Euler (covariance) contribution, with Σ the factor covariance over the fund's window:

C_k = β_k · (Σβ)_k share_k = C_k / Var(r) Σ_k share_k = R²

A negative share means the bucket hedges the fund's other exposures. Shapley R² is the order-independent alternative: the average marginal R² of bucket k across all 32 subset regressions. Use Shapley for the headline chart and Euler for the risk report.

6.4 Confidence intervals

Run a moving-block bootstrap (block length 6, 1,000 draws) and re-estimate the betas and shares each draw. Report 90% intervals. With 60 months, expect shares to be about ±10 percentage points wide.

OutputPer fund: betas (raw and shrunk), t-stats, shares with confidence intervals, α, R², VIF.
GateVIF < 5 for all factors. Residual ρ1 < 0.2 (if not, revisit Stage 05).

07Level 2: drill-down

Purpose

For buckets that matter, identify which regions or sub-classes drive the exposure.

7.1 Trigger

Drill into bucket k only if its Shapley share is ≥ 10% and βk is significant (|t| ≥ 2). Otherwise report the bucket as "global only."

7.2 Selection: stability selection

  1. Candidates: the orthogonalized spreads S̃ belonging to the triggered buckets.
  2. Partial out the five Level 1 factors from both the fund return and the candidates (Frisch–Waugh), so the core factors stay unpenalized.
  3. Standardize the candidates. Fit a Lasso with BIC-chosen penalty (LassoLarsIC).
  4. Repeat on 500 moving-block bootstrap samples (block length 6).
  5. Keep candidates with selection frequency ≥ 0.60. Cap at the top 3 across all buckets.

7.3 Refit and test

r_t = α + Σ_k β_k·F_k,t + Σ_j γ_j·S̃_j,t + ε_t
  • OLS with Newey–West standard errors.
  • Joint HAC Wald test on all γ. If p ≥ 0.05, discard the drill-down and report "global only."
  • Because S̃ is orthogonal to the core, the β's should barely move from Stage 06. A change of more than 1 standard error indicates an orthogonalization problem.

7.4 Attribution and translation

The bucket's total contribution is C_k + Σ_(j in k) C_j, which reconciles with Stage 06. For the reader, convert tilts into effective regional exposures:

Exposure_j ≈ β_k · w_j + γ_j (w_j = region weight in the global index)

Example: βEQ = 0.50, Japan weight 5%, γJapan = 0.30 → effective Japan exposure ≈ 0.33. That is roughly a 13× overweight relative to a passive global allocation.

OutputPer fund: selected spreads, selection frequencies, γ with t-stats, joint Wald p-value, regional shares.
GateNo more than 3 Level 2 factors. The joint test passes, or the fund is reported as "global only."

08Nonlinear extensions

Purpose

Capture option-like or asymmetric behaviour with at most one extra term per fund, keeping the model linear in parameters.

Detect first
  • Ramsey RESET test on the Stage 07 model (p < 0.05 → investigate).
  • Plot residuals against the dominant factor and look for a U-shape or kink.
  • Compare residuals in the worst 10% of equity months with the rest.

09Testing and validation

Purpose

Prove that the selected factors are real drivers rather than in-sample noise. Run all tests for every fund.

9.1 Walk-forward out-of-sample test (primary)

  1. Initial window: months 1 to 36. Expanding window, one-month step.
  2. At each step t: re-estimate the orthogonalization coefficients, re-run stability selection (200 draws is enough here), and fit the model on months 1 to t.
  3. Predict month t+1 using its realized factor returns. This is explanatory, not a forecast: it tests whether the betas hold on unseen months.
  4. Benchmark: the historical mean of the fund's return up to t.
R²_OOS = 1 − Σ(r − r̂_model)² / Σ(r − r̄_hist)²

This yields about 24 out-of-sample months. Also report the out-of-sample tracking error (standard deviation of prediction errors, annualized) versus the in-sample residual volatility. A ratio above 1.5 signals overfitting.

9.2 Drop-one test

For each Level 2 or 3 factor, rerun 9.1 without it. The factor is confirmed only if the out-of-sample tracking error worsens when it is removed.

9.3 Circular-shift permutation test

For each selected factor, circularly shift its series by a random offset (preserving its autocorrelation), refit, and record the t-stat. Repeat 1,000 times. The real t-stat must exceed the 95th percentile of the shifted distribution.

9.4 Stability

  • Split sample: fit on the first 30 and last 30 months separately. The beta sign must match, and magnitudes should be within 2 standard errors of each other.
  • Stress months: refit with a stress interaction. Report the stress beta separately.
  • Kalman beta: random-walk betas with small state noise (Q pooled across the peer group). Flag drift when the filtered beta leaves its 90% band for 3 or more consecutive months.

9.5 Robustness

  • Proxy swap: replace each Level 1 index with its runner-up from the Stage 03 cluster (for example, ACWI replaced by MSCI World). Conclusions must hold.
  • Raw vs unsmoothed: conclusions must hold in both runs, where applicable.

9.6 Multiple testing

Across the whole universe, apply Benjamini–Hochberg at a 10% false discovery rate to (a) all Level 2 and 3 factor p-values and (b) all α p-values. Report the FDR-adjusted q-values.

Economic plausibility check: the exposure must be consistent with the stated strategy, or explainable by the manager letter, risk report (e.g. Open Protocol) or holdings. An analyst writes one line of rationale for every Driver that is not obvious from the mandate.

10.2 Per-fund tearsheet

  1. Header: strategy, n months, smoothing flag, R² (in-sample and out-of-sample), α with q-value.
  2. Level 1 table: β (shrunk), confidence interval, Shapley share, Euler share.
  3. Level 2 table: selected spreads, γ, selection frequency, effective regional exposure, class.
  4. Charts: stacked risk-share bar (Level 1 → Level 2), Kalman beta paths, actual vs out-of-sample replica returns.
  5. Flags: drift, low confidence, style inconsistency with peers.

10.3 Universe views

  • Heatmap of funds × factors (shrunk betas, masked where not a Driver).
  • Portfolio aggregation: allocation-weighted sum of betas → total portfolio exposure per factor. This reveals hidden concentration, such as several "diversified" funds all carrying Japan equity or HY credit.
  • Crowding: correlation of funds' residuals; clusters of high residual correlation indicate a shared unmodelled factor.

11Monthly production run

  1. Load new month of fund and index data. Run Stage 01 checks.
  2. Recompute factors using the frozen factor_spec.yaml (the spec changes quarterly, not monthly).
  3. Run Stages 05 to 07 for all funds. Update Kalman betas.
  4. Compare with last month: flag any β that moved by more than 2 standard errors, any new or dropped Driver, and any bucket share change above 10 points.
  5. Run the full Stage 09 validation quarterly (it is compute-heavy). Monthly: Kalman drift check only.
  6. Analyst reviews flags and writes rationale. Record overrides in override_log.csv with name, date and reason.
  7. Archive inputs, config, code version (git hash) and outputs under runs/YYYY-MM/ so any past result can be reproduced.
Quarterly
  • Re-run the Stage 03 funnel with any new indices. Sign off and freeze the new spec.
  • Review strategy bucket assignments against the Level 1 results (for example, a "market-neutral" fund with βEQ = 0.6).
Governance
  • Model documentation: purpose, assumptions, limitations, this manual.
  • Independent validation before first production use, and annually after (per SR 11-7 practice).
  • Known limitations: 60-month samples, linear-in-parameters form, index proxies may differ from true holdings, and results describe exposure, not causation.

Redundancy clustering (Stage 03)

import numpy as np, pandas as pd
from scipy.cluster.hierarchy import linkage, fcluster
from scipy.spatial.distance import squareform

def cluster_indices(rets: pd.DataFrame, rho_cut=0.90):
    D = 1 - rets.corr().abs()
    Z = linkage(squareform(D.values, checks=False), method="average")
    return pd.Series(fcluster(Z, t=1 - rho_cut, criterion="distance"),
                     index=rets.columns)  # same label = same cluster

Orthogonalization (Stage 04)

def resid(A, B):
    """Residual of A (n,) or (n,m) on [1, B]."""
    Z = np.column_stack([np.ones(len(B)), B])
    coef, *_ = np.linalg.lstsq(Z, A, rcond=None)
    return A - Z @ coef, coef

Level 1 fit, Euler and Shapley (Stage 06)

import statsmodels.api as sm
from itertools import combinations
from math import factorial

def fit_hac(y, X, lags=3):
    return sm.OLS(y, sm.add_constant(X)).fit(
        cov_type="HAC", cov_kwds={"maxlags": lags})

def euler_shares(y, X, beta):
    S = np.cov(X, rowvar=False)
    return beta * (S @ beta) / np.var(y, ddof=1)

def shapley_r2(y, X):
    k = X.shape[1]
    r2 = {(): 0.0}
    for m in range(1, k + 1):
        for s in combinations(range(k), m):
            r2[s] = sm.OLS(y, sm.add_constant(X[:, list(s)])).fit().rsquared
    phi = np.zeros(k)
    for j in range(k):
        for s, v in r2.items():
            if j in s:
                continue
            w = factorial(len(s)) * factorial(k - len(s) - 1) / factorial(k)
            phi[j] += w * (r2[tuple(sorted(s + (j,)))] - v)
    return phi  # sums to full-model R²

Stability selection (Stage 07)

from sklearn.linear_model import LassoLarsIC

def block_boot_idx(n, block, rng):
    starts = rng.integers(0, n - block + 1, size=int(np.ceil(n / block)))
    return np.concatenate([np.arange(s, s + block) for s in starts])[:n]

def stability_select(y, core, cand, n_boot=500, block=6, seed=0):
    rng, n = np.random.default_rng(seed), len(y)
    hits = np.zeros(cand.shape[1])
    for _ in range(n_boot):
        i = block_boot_idx(n, block, rng)
        yr, _ = resid(y[i], core[i])          # partial out Level 1
        Cr, _ = resid(cand[i], core[i])
        sd = Cr.std(0); sd[sd == 0] = 1
        m = LassoLarsIC(criterion="bic").fit(Cr / sd, yr)
        hits += m.coef_ != 0
    return hits / n_boot                      # keep freq >= 0.60

Walk-forward validation (Stage 09)

def walk_forward(y, core, cand, start=36, thresh=0.6):
    pred, bench = [], []
    for t in range(start, len(y)):
        freq = stability_select(y[:t], core[:t], cand[:t], n_boot=200)
        keep = np.argsort(-freq)[:3]
        keep = keep[freq[keep] >= thresh]
        X = np.column_stack([core, cand[:, keep]])
        fit = sm.OLS(y[:t], sm.add_constant(X[:t])).fit()
        pred.append(fit.params @ np.r_[1.0, X[t]])
        bench.append(y[:t].mean())
    yt, pred, bench = y[start:], np.array(pred), np.array(bench)
    r2_oos = 1 - np.sum((yt - pred) ** 2) / np.sum((yt - bench) ** 2)
    te_oos = np.std(yt - pred, ddof=1) * np.sqrt(12)
    return r2_oos, te_oos

In production, the orthogonalization coefficients should also be re-estimated inside the loop using data up to t only.

Circular-shift permutation (Stage 09)

def perm_test(y, X, col, n=1000, seed=0):
    rng = np.random.default_rng(seed)
    t_real = abs(fit_hac(y, X).tvalues[col + 1])
    t_null = []
    for _ in range(n):
        Xp = X.copy()
        Xp[:, col] = np.roll(X[:, col], rng.integers(6, len(y) - 6))
        t_null.append(abs(fit_hac(y, Xp).tvalues[col + 1]))
    return np.mean(np.array(t_null) >= t_real)   # empirical p-value
